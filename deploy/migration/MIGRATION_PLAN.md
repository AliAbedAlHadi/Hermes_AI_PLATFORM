# Per-company identity migration (G2-2 rollout)

Owner decision 2026-10-30: one Windows account per company, all four stages in one run, stopping only where the
owner must run an elevated script. Stage 1 evidence: `inventory.py` (read-only), all checks PASS.

## Facts from the inventory (2026-10-30)

- 118 federation agents (5 companies x 22 + 8 federation) in one Hermes home, `%LOCALAPPDATA%\hermes`.
  8 other profiles (`company`, `hc*`) belong to another project and are **not** touched.
- Every agent: guard hook (fail-closed, own agent name), federation memory MCP, own `.env` (model keys).
- Every agent depends on three files in the owner's profile: Python 3.11 (`AppData\Local\Programs`), `fed_guard.py`
  and `memory_mcp.py` (OneDrive). Both scripts are stdlib-only and run on the runtime's Python 3.14.
- Shared state the agents open directly: `federation\memory.db` and `workflow.db` (WAL mode: the folder must be
  writable). The same folder holds owner-only files (`owner.json`, `sessions.db`, `conversations.db`, `models.json`).
- Boards are already per company (`kanban\boards\<company>`); the guard already confines each agent to its own.
- All 118 have the `hermes-cloud` MCP, whose OAuth token is the owner's: it is disabled for migrated agents.
- No Hermes gateway/dispatcher process runs; the Console starts every agent run.

`hermes-agent` stays as the pilot account.

## Stages

1. **Inventory** (done): `inventory.py`, read-only.
2. **Identities and canary**: owner runs `2_setup_identities.ps1` elevated once (accounts, folders, ACLs, the fed code
   copy, one Hermes dependency install per home: ~25 min, ~7 GB). Then, non-elevated, `canary.py` copies
   `isc-executor` (and only it) into `homes\isc`, rewrites its paths, and proves as `hermes-isc`: one chat turn, the
   guard registered, and the OS refuses other companies' homes/workspaces, the owner's profile and the live home.
3. **Cutover of the shared state + ISC**: Console stopped. `migrate.py --shared` copies memory.db/workflow.db to
   `shared` (originals kept as the rollback) and points the Console and every live profile's guard/memory tool at it.
   `migrate.py --group isc` copies the 22 ISC profiles, the ISC board and workspace into the new layout, rewrites
   paths, regenerates the hook approvals, disables hermes-cloud, and marks ISC migrated in `homes\layout.json` (owner-only: no identity can reroute itself); the
   Console then runs ISC agents as `hermes-isc`. Test: `verify_group.py isc` (OS probes + one turn + guard).
4. **Remaining groups**: the same for auvia, tabbeqai, spectra, spectrasolutions, federation; test each.

Live copies are never deleted: the old home stays as it is (rollback = `migrate.py --rollback <group>`, which
marks the group unmigrated again; writes made after cutover stay in the new home and are reported).

## Residuals (OPEN items stay open)

- **R1 shared memory**: every company identity can open `shared\memory.db` directly; per-company separation of memory
  is fedmem's scoping plus the guard, not the OS. Closing it needs a memory broker (follow-up).
- **R2 loopback**: Windows cannot restrict loopback per user (Ollama, Console) - G2-4.
- **R3 hermes-fed**: all 8 federation agents get OS read on every workspace (the guard limits it to fed-hermes-admin
  and fed-audit).

## How the Console follows the migration

`console/routing.py` reads `homes\layout.json` on every call (no restart needed for a rollback):
- a chat turn (`-p A -z ...`) or a board dispatch of a migrated group runs through `agent_runner` **as the group's
  identity**, starting in the group's workspace; only `FED_CUSTOMER` is passed to the agent;
- other commands on a migrated group (create/log/archive on its board, `hooks list`) run as the owner against the
  group's home with the runtime's `hermes.exe` (the home holds dependencies for that checkout only);
- profile reads/writes (agents list, model apply, key sync, health, map) use each profile where it lives;
- once `shared` is set, the Console opens `shared\memory.db` / `shared\workflow.db`;
- `security/fingerprint.py` and `integrity.py` follow the layout and also hash `C:\HermesFederation\fed`.
